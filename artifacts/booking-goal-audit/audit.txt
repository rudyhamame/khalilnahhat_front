CONFIRMED FINDINGS

F01 HIGH — Rental decision is omitted from the live review.
Authority: 04.01.01 rental.requested gates the rental section.
Evidence: src/lib/bookingReviewModel.js:25 explicitly filters it out when a
catalogue tree exists. The tree is then rendered regardless of this decision.
Reproduction: rental.requested=false with qsc-k122 quantity 2 still produces
the selected equipment tree, without a rental.requested row. This affects
Booking review, Concept map, and the client's editable draft review. Snapshot
views use a different path and can display the rental decision.
Impact: the client cannot review/confirm this numbered decision on those
surfaces; the documented rental gate is not applied there.
Correction: retain the rental decision row and define one shared gate policy.
Preserve saved items on decline unless explicitly removed, but make the
contradiction visible rather than hiding the decision.

F02 HIGH — Saved equipment can disappear from the live review.
Evidence: src/lib/bookingReviewModel.js:32-40 builds rows from today's catalogue;
when the tree exists, it does not append saved items missing from that tree.
Reproduction: order.equipment=[{id:'retired-speaker',name:'Saved retired speaker',
quantity:2}] produces no matching live review row with the production tree.
Impact: Booking review, Concept map and client draft can omit a saved selection,
so it is also absent from the atom confirmation list. Server validation may
reject an unavailable item later; hiding it is still a review failure.
Submitted snapshots preserve their captured equipment independently.
Correction: show missing/inactive saved items explicitly with a resolve/remove
state and include them in review validation.

F03 HIGH — Account names allow values that booking rejects or normalizes away.
Authority: 01.01.01 / 01.01.02, maximum 60 characters each.
Evidence: ClientProfile.jsx:48-49 permits 80; backend server.js:892-893 also
accepts 80. eventOrderContract.json limits both to 60.
Reproduction: importing a 70-character first name yields a customer.firstName
validation error; normalizeEventOrder then resets that invalid value to null.
Impact: a valid account profile can prevent booking completion.
Correction: use the 60-character contract limit at profile, signup, import and
server boundaries; handle existing oversized account values explicitly.

F04 HIGH — Admin cannot see the client's custom event type.
Authority: 02.01.02 event.title is required when event.type=other.
Evidence: AdminServicesPanel.jsx:24-40 manually builds sections and never reads
event.title; list/header display event.type. React server render with an
AUDIT_CUSTOM_EVENT marker returns no marker in the output.
Impact: the client explains the event, but the admin sees only Other.
Correction: include the conditional custom event type in the admin brief and
use it where the request's event type is summarized.

F05 HIGH — Suggested-song editor can overwrite a newer canonical song list.
Authority: 03.02.03 ordered songs must persist consistently across manual/AI edits.
Evidence: DjBookingForm.jsx:53-60 initializes local rows from suggestedSongs
only on mount; commit writes the entire local list. There is no synchronization
when canonical music.suggestedSongs changes while this editor stays mounted.
Scenario: open editor with song A; Echo adds song B; edit A in the still-open
editor; commit can write the old local list and drop B.
Confidence: confirmed by state/commit code inspection; mounted browser sequence
not exercised. Existing servicesAuditGuide.js also documents this risk.
Correction: reconcile canonical updates with incomplete local rows, or base
writes on the latest canonical list and stable song identities.

F06 MEDIUM — Admin loses attachment comments and song links in presentation.
Authority: 05.01.01 photos with comments; 05.01.03 documents with notes;
03.02.03 / 03.02.04 songs include their saved link where present.
Evidence: AdminServicesPanel.jsx:29 renders files as name/url anchors only;
its music rows at :37 omit link values. Server-rendered markers for photo
comment, document note and suggested-song link are absent.
Impact: those values are stored and visible in shared client review renderers,
but the administrator cannot read them in the structured booking brief.
Correction: reuse the shared reference/music value renderers in admin.

F07 MEDIUM — Echo instructions contradict the bible and shared chapter model.
Authority: 03.01.02 MC belongs to DJ Khalil service, not Rental equipment.
Evidence: backend src/event-order.js:37 explicitly says MC belongs ONLY to
chapter 04 and never chapter 03. Frontend bookingFlow.mjs:19-20 puts MC in 03.
Also backend event-order.js:45 calls Event title optional, whereas
missingOrderFields requires it for Other and ai-booking.js:54 tells Echo to
ask for it immediately.
Impact: text and voice receive competing rules; conversation can direct the
client to the wrong chapter or describe a conditional requirement incorrectly.
Correction: generate chapter ownership and conditional requirements from the
shared field/flow model and remove conflicting prose.

F08 MEDIUM — Optional DJ/MC answers are marked missing by progress logic.
Authority: 03.01.01 / 03.01.02 are optional.
Evidence: bookingNextStep.js:29-30 adds missing DJ and MC decisions when their
services exist. validateEventOrder(submission:true) does not require them.
Reproduction: a blank order produces missing DJ/MC in effectiveMissing, but
no corresponding DJ/MC validation errors. goalProgress uses effectiveMissing;
HomeBookingAssistant's submit readiness uses missingOrderFields instead.
Impact: review/map/client draft can say Needs attention while the submission
rules treat those answers as optional.
Correction: preserve optional semantics in completeness; prompting an optional
question must not turn it into a required answer.

F09 MEDIUM / ACKNOWLEDGED CLEANUP — Sound equipment codes differ from the bible.
Evidence: bookingReviewModel.js:34-36 generates item codes by catalogue position.
The live extra set is inserted at 04.02.02. The bible leaves that set unnumbered.
Examples: wedge monitors are live 04.02.03 versus bible 04.02.02;
QSC is live 04.02.07 versus bible 04.02.06; Soundcraft is live 04.02.11 versus
bible 04.02.10. Other listed sound entries after the set are shifted by one.
The item IDs, stock and minima match; this is a code/ordering mismatch.
Correction: complete the acknowledged catalogue cleanup or assign an explicit
numbering/exclusion rule. Do not reinterpret stock counts as permanent values;
the source document explicitly makes the live catalogue authoritative for stock.
No database cleanup was performed as part of this audit.

F10 MEDIUM — Dashboard views do not support the bible's Arabic presentation.
Evidence: BookingDraftReview.jsx:13 hardcodes tr=en=>en and :14 supplies ar=false;
headings are goal.title. DashboardPage, ClientProfile and AdminServicesPanel
also use English-only booking copy. Echo review/map accept Arabic.
Impact: the same atoms have Arabic labels in the contract and Echo surfaces,
but draft/request dashboard briefs do not select them.
Correction: pass the interface language into shared renderers and translate
surrounding labels if bilingual coverage is required across all named surfaces.

TEST DEBT (SEPARATE FROM A PRODUCTION DEFECT)
T01: bookingDraftEdits.test.js:63 fails at :69 because its speaker fixture has
only category:'sound', while current equipment membership reads
 equipmentCategoryId || serviceId. The pure edit helper expects normalized
catalogue equipment. Production /api/tree returns equipmentCategoryId.
This observed failure does not establish that live sound selection is broken.
Update the fixture to the current identity shape and keep a separate test for
legacy normalization at the tree boundary.
